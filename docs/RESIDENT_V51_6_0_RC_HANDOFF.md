## 已知限制

23:29 漏接管已经找到直接原因：持久化 mico.log.bak.1 中，最终 ASR、Template.Toast 与 Speak 均使用相同的合法 31 位十六进制 dialogId，而旧实现硬性要求 32 位。已统一 Supervisor/Agent/Frida/Host 为实机验证过的 31–32 位格式，ARM 回执不再固定下标切割；不补零、不把不同长度 ID 合并。白名单、来源、Owner、codec 和并发检查未放宽。增加真实格式回放、30/33 位及非十六进制拒绝、零补齐不混淆等回归。

先前候选曾在唤醒后出现 OEM 重载；纯原厂对照正常。移除共享计时方法 Hook、改用限定本轮的续期、延后开机注入后，多轮测试未再复现。尚不能把原始 ANR 唯一归因于某一个 Hook 或 EFS。

EFS 忙循环在未注入的原厂启动中可复现；原有定点恢复出现 3 次 ABORT 后线程转为休眠。启动早期曾出现带 Frida 映射的 ZIDThreadPoolEx fork 子进程持续耗 CPU，并阻断旧版 PID 检查。当前策略在本台 LX04 通过，不推定其他型号通用，不声称全面停用统计 SDK。

这仍是 RC 测试候选，非稳定版。保留 V51.5 与 recovery 包备份。真实猫眼视频、长时运行及偶发漏接管继续观察。午夜猫眼测试不得播放来访提示，不以全局静音代替单次提示音关闭。

## TTS 401 恢复
最终重启首轮发现小米 MIoT TTS 返回 HTTP 401。仅对确认的 401，使用现有验证过的 passToken 更新 xiaomiio SID 后重试一次；保留其他 SID，受请求取消约束，5 分钟内最多刷新一次。刷新拒绝时不转密码认证；429、403、网络超时均不触发该重试。Agent 新增 3 项恢复策略测试，MiService 增加 3 项缓存刷新测试及原有协议/限流测试全部通过。实机恢复结果另记。
