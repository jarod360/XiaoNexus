# XiaoNexus · 小爱智枢

**让小爱继续做好原厂的事，让 DeepSeek 接住它答不上的问题。**

XiaoNexus 是面向小米带屏音箱 LX04 的社区增强项目。仍然用“小爱同学”唤醒，保留原厂语音识别、设备控制、音乐和日常服务；当原厂明确无法回答，或你希望完善上一轮知识回答时，再由 DeepSeek 接续。

[功能原理](docs/ARCHITECTURE.md) · [部署说明](docs/DEPLOYMENT.md) · [版本与验证状态](docs/CURRENT_STATE.md) · [开源与致谢](#开源与致谢)

## 我们希望带来的体验

- **照常使用小爱。** 控制设备、播放音乐、查询原厂服务，继续走原有流程。
- **答不上来时再交给 DeepSeek。** 接管判定依据真实对话事件和原厂明确拒答，而不是提前按问题关键词猜测该由谁回答。
- **少一句拒答，多一个答案。** 成功接管的拒答任务会替换原厂拒答文字，并针对该任务阻止拒答音频，随后显示和播报 DeepSeek 回答。
- **可以继续追问和完善。** 对可关联的上一轮原厂知识回答，说“让 DeepSeek 完善一下刚才的回答”，把原问题与原答一并交给 DeepSeek 重新组织、补充或纠正。
- **等待过程更自然。** 使用原厂思考动画，让 DeepSeek 生成答案时仍有原生等待反馈，答案就绪后再交接到回答页面。

## 核心能力

### 按真实对话分流，减少关键词维护

原厂先完成唤醒、识别和自身处理。XiaoNexus 关联本轮对话 ID、事件来源、明确拒答与播放任务，符合条件才把这一轮交给 DeepSeek。

接管不依赖“天气留给小爱、含某个词就交给 AI”一类问题关键词黑白名单。这减少了新增设备、场景或自定义语音时维护通用分流词表的负担；具体任务仍以原厂实际支持情况和接管条件为准。

### 精确替换拒答，保留其他声音

成功门控的拒答任务可以改为“请稍等……”提示，抑制对应任务的拒答音频。处理范围限定在已关联的对话和音频任务，保留其他播放、结束标记和独立的 DeepSeek 播报。

来源不明、并发冲突、接收器不可用或条件失配时，优先放行原厂。它不是全局静音，也不承诺任何未知拒答话术都必定被拦截。

### 原厂显示与播报接续

DeepSeek 答案生成后，使用原厂文字页面显示内容，再调用小米原生 TTS 播报，无需另装一套回答应用。

原生等待动画复用真实 LX04 原厂资源，覆盖答案生成期间的等待，答案就绪后退出并交接到回答页。已完成可见效果、受控长等待、失败与超时退出测试，持续兼容性仍在观察。

### 理解“完善刚才的回答”

补充功能带有上下文关联：保存可识别的上一轮原厂知识问答，将原问题和原答提供给 DeepSeek，要求重新、准确地回答，而不是只把旧答案拉长。

这项能力不等同于无限多轮记忆；上下文缺失、过期或不能安全关联时，不会随意补写其他对话。相关边界仍在继续实测。

### 音箱本机运行

语音事件关联、接管监督和回答接收器运行在音箱上，日常使用无需常开电脑。原厂 APK 无需修改或重签；接收器仅监听本机回环地址。

模型推理和联网检索仍使用云端服务，原厂识别与播报沿用小米服务，因此不是离线助手。联网检索是否可用取决于配置及账户权限。

### 更稳妥地处理登录与鉴权

客户端保留已验证的账号身份、设备标识和凭据，使用缓存的 passToken 进行服务认证；临时网络故障不会直接清空已验证身份。遇到小米明确的账号限流码时，不继续尝试密码登录；验证码与二次验证单独处理。

运行环境使用设备 DHCP 提供的 DNS，并加载 Android 系统 CA，保留正常 TLS 校验。目标是减少环境故障与不必要的反复认证，而不是用关闭证书校验换取登录成功。

确认 TTS 返回 HTTP 401 时，使用缓存 passToken 刷新对应服务凭据并重试一次，5 分钟内最多刷新一次；拒绝时不回退密码登录。429、403 和网络超时不会触发该恢复。

**这些措施不能保证云端永不返回 HTTP 429。** 云端限流、账号风控、验证要求和服务可用性仍需按实际响应处理，不能把重试或重启当作通用解法。

## 一轮接续如何发生

1. 你照常唤醒并提问，原厂先处理。
2. 原厂正常完成的任务继续留在原有链路。
3. 遇到已匹配的明确拒答，或可关联的“完善上轮回答”请求，XiaoNexus 尝试精确接管。
4. DeepSeek 生成答案，随后交给原厂页面和 TTS。
5. 本轮结束或失效后释放接管状态，继续响应下一次唤醒。

## 适用与部署

目前以 **LX04 / Android 8.1 / ARMv7** 的真实原厂 APK 为适配依据，尚不能据此推定其他型号或固件通用。部署需要认证 root ADB、匹配版本的组件与独立的官方 Frida 16.6.6 android-arm 工具，以及有效的小米和模型服务配置。

首次使用请先阅读[部署说明](docs/DEPLOYMENT.md)与[构建变体说明](docs/BUILD_VARIANTS.md)。版本包中的 Agent、Supervisor、Hook 和常驻脚本应保持匹配，保留备份和停用入口。

测试进程、校验值、回滚记录与完整验收边界集中放在[当前状态](docs/CURRENT_STATE.md)、[实机交接](docs/RESIDENT_EFS_V51_5_HANDOFF.md)和[验证记录](docs/VALIDATION.md)，不把阶段性成功写成所有场景均已通过。
